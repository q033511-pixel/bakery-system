### 3. اختبارات الخادم الحقيقي — `tests/server/` (41 اختباراً) ⭐ جديد

تعمل ضد **PostgreSQL فعلي** بعد تطبيق الـmigrations الثمانية من قاعدة نظيفة + حاضنة توافق Supabase المحلية (`supabase/dev/local_shim.sql` — لا تُطبق على مشروع سحابي):

| القسم | التغطية |
|---|---|
| §1-2 التهيئة والدوال | bootstrap حقيقي، شراء→متوسط مرجح، بيع→صندوق+مخزون، **idempotency على مستوى القاعدة** (duplicate:true + حركة واحدة)، كسر مخزون يُرفض بلا أثر، **حد ائتمان مفروض على الخادم**، حل السعر الخاص (3.8/3.0/عام) |
| §3 RLS فعلي | عزل نشاطين كاملين، anon لا يرى شيئاً، VIEWER يقرأ ولا يبيع، محاسب مصروف نعم وبيع لا |
| §4 هوية الأجهزة | رمز لكل جهاز (sha256 يخزن فقط)، إبطال فوري، تدوير (القديم يموت)، صلاحيات تتبع الإنسان لا الآلة |
| §5 بروتوكول المزامنة | APPROVED بنتيجة، DUPLICATE بلا أثر مالي مضاعف، REJECTED بسبب عربي وصفر أثر، سحب بترتيب seq، رفض بلا هوية إنسان/آلة |
| §6 السيناريوهات العشرة بجهازين | عميل من الموقع يظهر في EXE والعكس، تحصيل ورصيد متطابق، شراء ومخزون/مورد متسقان، انقطاع→تسجيل محلي→عودة، إعادة إرسال بلا تكرار، **جهازان يبيعان نفس الكمية: الأول يعتمد والثاني يُرفض مسبباً**، رفض ائتمان، منع نشاط آخر من الرؤية والسحب، إيقاف قسري→إعادة إرسال آمنة |
| §7 تجربة الترحيل | معاينة أعداد → رفع لمخطط منفصل → مطابقة أعداد ومجاميع (فروقات صفر) → الأصل سليم ولم يُمس |

### 4. تشغيل اختبارات الخادم محلياً وCI

```bash
# محلياً (PostgreSQL مدمج 17.10 — بلا Docker): راجع بيئة التجربة
TEST_DATABASE_URL="postgres://..." npx vitest run tests/server

# بدون TEST_DATABASE_URL تُتخطى اختبارات الخادم تلقائياً (لا فشل وهمي)

# CI (GitHub Actions — tests.yml): خدمة postgres:17 + تطبيق migrations + كل الاختبارات
APPLY_SHIM=1 TEST_DATABASE_URL=... node scripts/apply-migrations.js && npx vitest run
```

على مشروع Supabase سحابي حقيقي: نفس السكربت بلا APPLY_SHIM وبسلسلة اتصال المشروع — نفس الاختبارات تعمل كما هي.
