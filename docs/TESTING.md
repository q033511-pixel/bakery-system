### 3. اختبارات الخادم الحقيقي — `tests/server/` (41 اختباراً)

تعمل ضد **PostgreSQL فعلي** بعد تطبيق الـmigrations الثمانية من قاعدة نظيفة + حاضنة توافق Supabase المحلية (`supabase/dev/local_shim.sql` — لا تُطبق على مشروع سحابي):

| القسم | التغطية |
|---|---|
| §1-2 التهيئة والدوال | bootstrap حقيقي، شراء→متوسط مرجح، بيع→صندوق+مخزون، **idempotency على مستوى القاعدة** (duplicate:true + حركة واحدة)، كسر مخزون يُرفض بلا أثر، **حد ائتمان مفروض على الخادم**، حل السعر الخاص (3.8/3.0/عام) |
| §3 RLS فعلي | عزل نشاطين كاملين، anon لا يرى شيئاً، VIEWER يقرأ ولا يبيع، محاسب مصروف نعم وبيع لا |
| §4 هوية الأجهزة | رمز لكل جهاز (sha256 يخزن فقط)، إبطال فوري، تدوير (القديم يموت)، صلاحيات تتبع الإنسان لا الآلة |
| §5 بروتوكول المزامنة | APPROVED بنتيجة، DUPLICATE بلا أثر مالي مضاعف، REJECTED بسبب عربي وصفر أثر، سحب بترتيب seq، رفض بلا هوية إنسان/آلة |
| §6 السيناريوهات العشرة بجهازين | عميل من الموقع يظهر في EXE والعكس، تحصيل ورصيد متطابق، شراء ومخزون/مورد متسقان، انقطاع→تسجيل محلي→عودة، إعادة إرسال بلا تكرار، **جهازان يبيعان نفس الكمية: الأول يعتمد والثاني يُرفض مسبباً**، رفض ائتمان، منع نشاط آخر من الرؤية والسحب، إيقاف قسري→إعادة إرسال آمنة |
| §7 تجربة الترحيل | معاينة أعداد → رفع لمخطط منفصل → مطابقة أعداد ومجاميع (فروقات صفر) → الأصل سليم ولم يُمس |

### 4. اختبارات طبقة النقل الحقيقية — `tests/server/transport-postgrest.test.ts` (10 اختبارات) ⭐ جديد

ناقل التطبيق **الفعلي** (`src/lib/sync/supabaseTransport.ts` — نفس الكود الذي سيشغله الموقع/EXE) يتحدث HTTP فعلياً عبر بوابة `/rest/v1` إلى **PostgREST 12.2.12 حقيقي** (نفس محرك الـAPI الذي يشغله Supabase السحابي) فوق PostgreSQL 17:

| السيناريو | الإثبات |
|---|---|
| RP-1 تسجيل جهازين عبر HTTP | رمز 64-hex يُعرض مرة واحدة، القاعدة تخزن هاشاً فقط (فحص صريح) |
| RP-2 رفع عبر الناقل | CUSTOMER_UPSERT → APPROVED والصف في القاعدة |
| RP-3 إعادة الإرسال عبر HTTP | DUPLICATE — صف شراء واحد وحركة صندوق واحدة (−350) |
| RP-4 جهازان عبر HTTP | بيع من win → web يسحب بـseq ويرى نفس رقم المستند |
| RP-5 كسر مخزون عبر HTTP | REJECTED بالسبب العربي + صفر صفوف + المخزون سليم + الرفض يصل للجهاز الآخر |
| RP-6 JWT مزوّر | PostgREST يرفض **401** (تحقق توقيع فعلي بمفتاح الاختبار) |
| RP-7 رمز جهاز خاطئ | رفض عربي «الجهاز غير مصرّح» عبر HTTP |
| RP-8 إبطال/تدوير عبر HTTP | الرمز المبطل يموت فوراً، التدوير يجدد السر والقديم يفنى |
| RP-9 عزل RLS عبر HTTP | نشاط ثانٍ يرى صفر صفوف، anon مرفوض (بعد **تسريب EXECUTE اكتشفته هذه الاختبارات وأُصلح في 0008**)، VIEWER → REJECTED بصلاحية عربية بلا أثر |
| RP-10 محرك كامل فوق HTTP | طابور دائم → رفع بترتيب التبعيات (عميل قبل فاتورته) → SYNCED → سحب وتطبيق → القاعدة تحمل العميل والفاتورة |
