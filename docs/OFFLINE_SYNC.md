# المزامنة والعمل أوفلاين — OFFLINE_SYNC.md

## المبدأ (بند 40)

**العملية لا تضيع أبداً.** عند ضعف/انقطاع الإنترنت يستمر التسجيل طبيعياً؛ البيانات تُحفظ في IndexedDB وترفع تلقائياً عند عودة الاتصال.

## التدفق

```
تسجيل عملية (بيع/شراء/تحصيل/إنتاج/...)
        │
        ├── متصل ──── RPC فوري ── نجاح → toast "تم الحفظ" (SYNCED)
        │                 └── خطأ عمل (مخزون/صلاحيات) → رسالة عربية واضحة، لا حفظ
        │                 └── خطأ شبكة → يُدرج في الطابور (PENDING)
        │
        └── غير متصل ── يُدرج فوراً في الطابور (PENDING)
                          → toast "تم الحفظ محلياً وسيتم مزامنته"
```

## المكوّنات

### 1. Dexie (`src/db/db.ts`)
- `pending_ops`: الطابور — `{operation_id (unique), type, payload, status: PENDING|SYNCING|SYNCED|FAILED, attempts, last_error, created_at, synced_at, summary}`
- `cache_*`: بيانات العمل للعرض أوفلاين (عملاء، أصناف، وحدات، مستودعات...) — تُحدّث عند الاتصال (`refreshLookups`).

### 2. محرك المزامنة (`src/services/sync/syncEngine.ts`)
- **enqueue**: dedupe بالـ operation_id — نفس العملية لا تُدرج مرتين.
- **drainQueue**: FIFO بترتيب الإنشاء؛ يعاد استدعاؤها عند حدث `online`، ودورياً كل 45 ثانية عند وجود معلقات، وبعد كل عملية.
- **retry**: خطأ شبكة أثناء التفريغ يوقف المحاولة مؤقتاً (تبقى PENDING)؛ خطأ عمل يحوّل العملية إلى **FAILED** مع رسالة واضحة وزر إعادة محاولة/تجاهل في مركز المزامنة.
- **dedupe على الخادم**: الـ RPC يعترف بالـ operation_id المكرر ويعيد النتيجة الأصلية — لا ازدواجية حتى مع تعدد الأجهزة (بند 43: server authoritative).

### 3. التعارضات (بند 43)
- المخزون يُتحقق منه **لحظة التنفيذ على الخادم** — جهازان باعا آخر 10 وحدات: الأول ينجح، الثاني يُرفض برسالة عربية ويظهر FAILED للمستخدم. **لا تجاوز صامت أبداً.**
- سياسة المخزون السالب قابلة للضبط من الإعدادات (`allow_negative_stock`, الافتراضي ممنوع) مع رفض صريح.

### 4. واجهة الحالة (بند 47/91)
شارة دائمة في الشريط العلوي: `● متصل ومتزامن` / `○ غير متصل (N عملية معلقة)` / `جارٍ المزامنة (N)` / `N عملية فاشلة`.
مركز المزامنة (`#/sync`): تفصيل كل عملية مع زر "مزامنة الآن" و"إعادة محاولة الفاشلة" وسبب فشل كل عملية فاشلة.

## ضمانات الاختبار (بند 81)

سيناريو `tests/syncQueue.test.ts`:
1. أوفلاين → بيع → العملية PENDING في IndexedDB ✓
2. محاكاة refresh (قراءة الطابور) → العملية موجودة ✓
3. عودة الاتصال → drainQueue → SYNCED، والخادم استلمها مرة واحدة ✓
4. إعادة التفريغ بنفس operation_id → الخادم idempotent، لا تكرار ✓
