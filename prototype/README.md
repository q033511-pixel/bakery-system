# نموذج المزامنة الأولي — إثبات انتقال البيانات بين الموقع ونسخة الويندوز

> **الحالة:** مُختبر — 11/11 سيناريو جهازين ناجح (2026-10-15) | **البيانات:** تجريبية فقط، لا علاقة ببيانات الزبون
> **الفصل:** هذا الفرع `sync-prototype` مستقل تماماً عن main — لا يعدّل التطبيق المنشور ولا قاعدة بيانات الإنتاج

## ما الذي يثبته هذا النموذج؟

1. **عقد المزامنة** المقترح (طابور عمليات + خادم مركزي idempotent) يعمل فعلياً بين **جهازين حقيقيين منفصلَي التخزين**:
   - جهاز أ = «الموقع» (Electron مستقل بـuserData خاص)
   - جهاز ب = «نسخة الويندوز» (Electron مستقل بـuserData خاص)
   - الخادم = وقوف مكان Supabase PostgreSQL بعقد مطابق (POST /v1/ops idempotent + GET /v1/changes + مصادقة Bearer لكل جهاز)
2. **آلة الحالات 7 حالات** تعمل: LOCAL_ONLY → PENDING_SYNC → SYNCING → SYNCED / REJECTED / FAILED / CONFLICT
3. **السلامة المالية**: المخزون يُتحقق لحظة التطبيق على الخادم (الأول يفوز والثاني يُرفض برسالة عربية)، تعويض كامل للتطبيق المتفائل عند الرفض، منع التكرار بـoperation_id، حد الائتمان مفروض من الخادم مع باب تجاوز صريح، والفواتير التاريخية لا يتغير سعرها أبداً
4. **البقاء**: الحالة على IndexedDB (دلالات Dexie نفسها) — المعلقات تنجو من قتل قسري وإعادة تشغيل

## التشغيل

```bash
# 1) الخادم (نود بلا أي اعتماديات)
node prototype/server/server.mjs          # :7777 — بيانات تجريبية في prototype/server/data

# 2) جهازان (يمثلان الموقع وEXE) — بيئة تجريبية منفصلة
E=/path/to/desktop/node_modules/.bin/electron
DISPLAY=:0 PROTO_DEVICE=device-site $E prototype/electron-main --remote-debugging-port=9323 --user-data-dir=/tmp/proto-dev-a
DISPLAY=:0 PROTO_DEVICE=device-exe $E prototype/electron-main --remote-debugging-port=9324 --user-data-dir=/tmp/proto-dev-b

# 3) اختبارات الجهازين العشرة
NODE_PATH=<tools>/node_modules node prototype/tests/two-devices.cjs
```

## الملفات

| الملف | الدور |
|---|---|
| `server/server.mjs` | الخادم الوسيط — عقد idempotent + سياسات مالية + مصادقة أجهزة + خدمة الواجهة |
| `web/sync-engine.mjs` | محرك العميل — 7 حالات + طابور + سحب بالـcursor + تعويض + بقاء IndexedDB |
| `web/index.html` + `app.js` | واجهة تجريبية عربية RTL: تسجيل عمليات، قطع اتصال، إرسال مزدوج، عرض الحالات والأرصدة |
| `electron-main/main.cjs` | غلاف Electron لكل جهاز (هوية + رمز عبر البيئة) |
| `tests/two-devices.cjs` | السيناريوهات العشرة آلياً عبر CDP |

## النتيجة الكاملة

انظر `SYNC_PROTOTYPE_RESULTS.md` في جذر الفرع — سجل السيناريوهات 1-10 + المطابقة النهائية + النتائج القابلة للقياس والمقارنة مع PowerSync.

## حدود صادقة (ما لا يثبته هذا النموذج)

- الخادم **وقوف مكان** مكتوب بـNode — الإنتاج سيكون Supabase PostgreSQL (المخطط والدوال موجودة أصلاً في `supabase/migrations 0001-0006`)؛ **RLS لم يُختبر بعد على خادم حقيقي**
- نموذج عمل واحد (نشاط واحد، جهازان) — التعدد المتقدم (فروع/أدوار عبر أجهزة كثيرة) يحتاج توسعة
- عمليات النموذج (بيع/تحصيل/سعر) subset من 44 معالجاً حقيقياً — الترحيل الكامل عمل منظم لا بحث
- لا تشفير إضافي ولا إدارة مفاتيح — مرتبط بقرار الاستضافة
