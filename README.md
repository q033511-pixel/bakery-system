# نظام إدارة المخبز 🍞

نظام تشغيل رقمي متكامل لمخبز كبير — يحول العمل اليدوي والدفاتر إلى نظام مركزي سريع وقابل للتتبع، يعمل **من الهاتف**، و**أوفلاين** عند ضعف الإنترنت، وبياناتك محفوظة على جهازك (مع ناقل بيانات لنقلها بين الأجهزة).

> **المسار الكامل:** المورد ← شراء ← مخزون مواد خام ← إنتاج ← منتجات نهائية ← مبيعات/توزيع ← عملاء ← تحصيل ← صندوق ← مصاريف ← تقارير ← ربحية تقديرية — كلها مترابطة، وكل رصيد **يُحسب من الحركات** لا يدوياً.

---

## ✨ الميزات

| الوحدة | التفاصيل |
|---|---|
| **لوحة التحكم** | مبيعات/تحصيل/مشتريات/إنتاج/مصروفات اليوم، ديون العملاء، مستحقات الموردين، قيمة المخزون، تنبيهات النقص — كلها من قاعدة البيانات (RPC واحد، بلا N+1) |
| **البيع السريع** | شاشة Mobile-first: تسجيل بيع خلال ثوانٍ، أصناف ±، أسعار تلقائية، نقدي/آجل |
| **المشتريات** | فواتير بمواد متعددة، تحديث التكلفة المرجحة تلقائياً (Weighted Average)، آجل/نقدي |
| **المخزون** | سجل حركات مركزي `inventory_movements` (13 نوع حركة)، لا أرصدة يدوية أبداً، تسويات، هالك، مناقلات بين المستودعات |
| **الإنتاج والوصفات** | دفعات إنتاج بحساب استهلاك المواد من الوصفة، **نسخ وصفات (Versioning)** — الإنتاج القديم يحتفظ بنسخته |
| **التوزيع** | سيارات، سائقون، حمولات، بيع أثناء الجولة، مرتجعات، **معادلة المطابقة**: المحمول = المبيع + المرتجع + الفرق، تسوية لا تُغلق دون معالجة الفروق |
| **دفتر الذمم (v8.2.0)** | رصيد كل عميل يُحسب من الحركات + رصيد افتتاحي معتمد + أعمار ديون (30/60/90+) + حد ائتمان يُفرض عند الحفظ بتأكيد صريح عند التجاوز |
| **أسعار خاصة لكل عميل (v8.2.0)** | قاعدة سعر (عميل × صنف/وحدة) بمدة صلاحية — الفاتورة تنسخ السعر لحظة البيع بشارة «سعر خاص»، **فلا تتغير الفواتير التاريخية أبداً** |
| **إقفال الصندوق اليومي (v8.2.0)** | إقفال واحد لكل (حساب × يوم) مع عدّ فعلي وفرق مسبب إلزامياً |
| **استيراد Excel/CSV (v8.2.0)** | معاينة قبل الاعتماد + توحيد تواريخ (ISO/DD-MM) + كشف تكرار + نسخة أمان تلقائية + تراجع |
| **الحسابات** | كشوف عملاء وموردين (مدين/دائن/رصيد), صندوق بحسابات متعددة، مصاريف مصنفة |
| **التقارير** | 13 تقريراً مع فلاتر تاريخ وتصدير CSV متوافق Excel، ربحية **تقديرية** مع تنبيه صريح |
| **الصلاحيات** | 8 أدوار + PENDING — مفروضة في محرك العمليات محلياً (RLS عند تفعيل الخادم مستقبلاً) |
| **سجل التدقيق** | كل عملية حساسة (إنشاء/تعديل/إلغاء/دفع/إنتاج/تسوية) مع before/after |
| **Offline-First** | IndexedDB كامل + طابور عمليات محلي idempotent — العملية لا تضيع حتى مع إغلاق التطبيق |
| **PWA** | قابلة للتثبيت على الهاتف، تعمل بدون إنترنت بالكامل (البيانات على جهازك) |

## 🧱 التقنيات

- **Frontend:** React 18 + TypeScript (strict) + Vite 6
- **UI:** Tailwind CSS 3 — عربي أولاً، RTL، Mobile-First
- **Routing:** React Router 7 — **HashRouter** (يعمل على GitHub Pages بلا rewrites)
- **التخزين الحالي (v8.2.0):** محلي بالكامل — Dexie (IndexedDB) عبر طبقة adapter تحاكي واجهة Supabase حرفياً (نفس أسماء الدوال ورسائل الأخطاء العربية)
- **Backend المستهدف (اختياري):** Supabase (PostgreSQL 15 + Auth + RLS + RPCs معاملية) — الـSQL جاهز في `supabase/migrations` لكنه **غير مفعّل في الإنتاج بعد**
- **النقل بين الأجهزة:** ناقل بيانات JSON يدوي (تصدير/استيراد) — **لا مزامنة سحابية في هذه النسخة** (القرار المعماري معلق على اعتماد الزبون: `SYNC_ARCHITECTURE_DECISION.md`)
- **PWA:** vite-plugin-pwa (Workbox precache)
- **النشر:** GitHub Pages + GitHub Actions
- **الاختبارات:** Vitest (**86 اختباراً في 9 ملفات**) + اختبارات SQL لسيناريوهات المواصفة

## 🔄 المزامنة — الواقع الحالي (v8.2.0)

> **بصراحة كاملة:** هذه النسخة **لا تملك مزامنة سحابية** — لا خادم، لا حسابات، لا رفع تلقائي.

- كل جهاز (الموقع / نسخة الويندوز) يخزن بياناته محلياً (IndexedDB) — قاعدتا بيانات **منفصلتان تماماً**.
- النقل بين جهازين = **ناقل البيانات اليدوي**: تصدير ملف JSON من جهاز واستيراده على الآخر (استبدال واعٍ بنسخة أمان تلقائية).
- طابور `pending_ops` محلي بحت — طبقة أمان ضد الفشل المحلي، **لا يرسل شيئاً لأي مكان**.
- قرار المزامنة المركزية (مقارنة Supabase/PowerSync/محلي) موثق في `SYNC_ARCHITECTURE_DECISION.md` ومعلق على اعتماد الزبون وتكلفته.

## 🔑 النشر السحابي على Supabase (اختياري — غير مفعّل في الإنتاج الحالي)

> ⚠️ **الوضع الحالي:** الموقع والEXE يعملان محلياً بدون Supabase. هذا القسم لمن يريد تفعيل الخادم المركزي لاحقاً بعد اعتماد قرار المزامنة.

1. أنشئ مشروعاً في [supabase.com](https://supabase.com).
2. **Migrations:** من SQL Editor نفّذ الملفات بالترتيب:
   `0001_schema.sql` → `0002_functions.sql` → `0003_rls.sql` → `0004_views.sql` → `0006_customer_pricing_debt.sql`
   (أو `supabase db push` مع CLI).
   ⚠️ `0005_seed.sql` بيانات تجريبية للتطوير فقط — لا تنفذها في الإنتاج.
3. **رمز التهيئة:** `select setup_code from system_setup;`
4. **Auth:** من Authentication → Providers فعّل Email. عطّل Confirm signup إن أردت دخولاً فورياً.
5. **أول مالك:** من التطبيق: «إنشاء حساب جديد» ← تسجيل دخول ← صفحة **تهيئة النظام** ← أدخل رمز التهيئة واسم المخبز. (التهيئة تعمل مرة واحدة وتُنشئ الوحدات والمستودعات والصندوق والفئات.)
6. **بيئة الإنتاج:** في إعدادات مستودع GitHub أضف Variables:
   `VITE_SUPABASE_URL` و `VITE_SUPABASE_PUBLISHABLE_KEY` ← ثم أعد تشغيل الـworkflow.

> 🔒 **أمنياً:** مفتاح Publishable (anon) فقط في الواجهة — service_role لا يُدخل أبداً في المتصفح أو المستودع.

## 📲 PWA

- التثبيت: من متصفح الهاتف «إضافة إلى الشاشة الرئيسية».
- أوفلاين: كل الشاشات تعمل؛ العمليات تُحفظ محلياً على جهازك — **لا رفع تلقائي لأي خادم (لا يوجد خادم بعد)**.
- Service Worker: precache للتطبيق + **NetworkOnly** لكل استدعاءات Supabase (لا كاش لبيانات حساسة).

## 🧪 الاختبارات

- **Vitest (86 اختباراً / 9 ملفات):** الحسابات المالية، تحويل الوحدات، سيناريوهات المواصفة 76-79 (مخزون 128، عميل 900، مورد 1100، توزيع فرق 50)، الطابور وidempotency، محرك العمليات المحلي (8)، PIN (7)، ناقل البيانات (4)، **التسعير الخاص (30)**، **محرك الذمم (11)**.
- آخر تشغيل موثق: **86/86 ناجح** (راجع `docs/TESTING.md` للتفصيل).
- **SQL (`supabase/tests/ledger_tests.sql`):** نفس السيناريوهات ضد قاعدة PostgreSQL حقيقية + منع البيع من مخزون غير متوفر + منع تكرار operation_id — تُشغل عند تفعيل الخادم بجلسة المالك بعد التهيئة.

## 📦 النسخ الاحتياطي — الواقع الحالي

- بياناتك على جهازك (IndexedDB): **ناقل البيانات** يصدّر ملف JSON كامل — استخدمه كنسخة احتياطية دورية (راجع `BACKUP_RESTORE.md`).
- الاستيراد ينشئ **نسخة أمان تلقائية** قبل الاستبدال ويدعم التراجع.
- النسخ السحابي (Supabase Pro / `pg_dump`) يُفعّل فقط إذا اعتمد قرار المزامنة المركزية — راجع `DEPLOYMENT.md`.
